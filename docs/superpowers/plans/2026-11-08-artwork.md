# Artwork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store TMDB, AniList and existing Open Library ids for works, and show their posters and
covers by linking live to the source, with credit, without storing any art.

**Architecture:** Three new `IdScheme`s, mapped by the Wikidata importer and added to existing works
by the backfill. A new `features/art` API feature resolves a batch of works to image URLs through
three polite source clients (TMDB, then Open Library, then AniList), cached in memory, behind
`GET /api/art`. The web app fetches art for a page's works in one call and renders posters,
thumbnails, placeholders and credits.

**Tech Stack:** Hono + `@hono/zod-openapi`, Drizzle on PGlite for tests, React + TanStack Query,
vitest. No new dependencies (cache and limiter are small in-repo code; XII).

**Spec:** `docs/superpowers/specs/2026-11-07-artwork-design.md` (approved 2026-11-08). Read it
first; it is the authority. Related: `docs/superpowers/specs/2026-11-05-wikidata-importer-design.md`.

## Global Constraints

- Constitution `CLAUDE.md` binds: III (writes only via `features/changes/apply.ts`), VI (PGlite; only
  external services faked, through injected deps), VIII (feature folders and layers), IX (casts and
  `!` get why-comments), X (value lists are `text`; uniqueness clash is 409 or idempotent), XI (one
  error shape; no catch-and-continue), XIII (delete what you replace).
- No non-CC0 value (image URL, poster path, cover id) is ever written to the database.
- New schemes: `tmdb_movie` (P4947, `^[1-9]\d{0,7}$`), `tmdb_tv` (P4983, `^[1-9]\d*$`), `anilist`
  (P8729, `^[1-9]\d*$`).
- Source order: `tmdb_movie`, `tmdb_tv`, `openlibrary`, `anilist`. Move on only on `none`; stop on
  `unavailable`.
- Timeouts and limits: whole request deadline 3 s; TMDB 20/s, Open Library 5/s, AniList 20/min;
  honor `Retry-After`; `/api/art` at most 50 ids, per-IP limit 120 requests/min (429).
- Cache: `found` 7 days, `none` 1 day, `unavailable` never; bounded at 20,000 entries.
- Image sizes: TMDB `w154` thumb / `w500` full from `https://image.tmdb.org/t/p/`; Open Library
  `M` thumb / `L` full.
- Outbound User-Agent: `AMDB/0.1 (https://github.com/cake-in-a-paw/amdb)`.
- `TMDB_API_KEY` optional; unset means every TMDB lookup is `unavailable`, plus one startup warning.
  Never logged, never in an error message (if sent as `api_key=` in the URL, never log the URL).
- Copy: credits "Poster: TMDB", "Cover: Open Library", "Cover: AniList"; alt "Poster for {title}" /
  "Cover for {title}"; footer notice exactly "This product uses the TMDB API but is not endorsed or
  certified by TMDB."
- American spelling. Conventional commits, scopes `api|web|shared|db|adr|ci`; docs use `docs:`.
  Commits signed with the on-disk key (the dispatch gives the command). `pnpm check` green before
  each task's last commit.
- OpenAPI snapshot is regenerated, never hand-edited:
  `pnpm --filter @amdb/api openapi:dump > apps/api/test/fixtures/openapi.snapshot.json` then
  `pnpm --filter @amdb/shared gen:api`.

## Review Focus

1. A list page of 20 uncached books: the first response has some `unavailable`, the retry fills
   more, and nothing hangs past ~3 s per call. (Task 2 test: deadline; Task 3 test: retry once.)
2. Two works in one backfill run carrying the same new TMDB id: the first gets it, the second is
   still backfilled with its other additions and counts `idsSkippedHeld`, not `skipped.invalid`.
   (Task 1 test.)
3. A TMDB 429 with `Retry-After: 30`: that lookup and the following ones are `unavailable` until 30 s
   pass, with no AniList stand-in. (Task 2 test.)
4. A `TMDB_API_KEY` must never appear in logs, errors or responses, even on a failing call.
   (Task 2 test: the key string is absent from the response body and from captured log output.)
5. The art endpoint for a removed, merged-away or non-work id reveals nothing more than entity reads
   do: `none`, or the winner's art for a merge. (Task 2 test.)

**Interfaces:**
- Produces (`sources.ts`):
  ```ts
  export type ArtImage = { thumb: string; full: string; link: string };
  export type SourceName = 'tmdb' | 'openlibrary' | 'anilist';
  export type Lookup = { status: 'found'; image: ArtImage } | { status: 'none' } | { status: 'unavailable' };
  export interface ArtSource {
    name: SourceName;
    schemes: readonly IdScheme[];
    lookup(scheme: IdScheme, value: string, deadline: number): Promise<Lookup>;
  }
  export interface ArtDeps { fetch: typeof fetch; tmdbApiKey?: string; now?: () => number; sleep?: (ms: number) => Promise<void> }
  export function createArtSources(deps: ArtDeps): ArtSource[]; // in the fixed order
  ```
- Produces (`outbound-limit.ts`): `createOutboundLimit({ limit, intervalMs, now?, sleep? })` returning
  `{ acquire(deadline: number): Promise<boolean>; blockUntil(t: number): void }`. `acquire` waits for
  room and returns false if none comes before `deadline` or while blocked.
- Produces (HTTP): `GET /api/art?works=<uuid>,…` returning
  `{ items: Record<string, { status: 'found'; source: SourceName; thumb: string; full: string; link: string } | { status: 'none' } | { status: 'unavailable' }> }`,
  keyed by the ids as requested. A bad uuid, 0 ids or more than 50 is 400; over the per-IP limit is 429.
- Produces: `AppDeps.art?: ArtDeps`. Omitted means no sources: every work is `none` and nothing is
  fetched. This keeps every existing test and the OpenAPI dump offline.
