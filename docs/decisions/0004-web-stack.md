# 0004. Web stack

- **Status:** proposed
- **Date:** 2026-11-03

## Context

ADR 0002 picked a React + Vite single-page app with TanStack Router and Query and Tailwind. The
web app (plan 2) is a public catalog browser, a submission tool and a moderation queue on the
API's OpenAPI contract. The constitution pins every version exactly (XII), forbids hand-written
API types (IX), and wants tests on the real API against PGlite with only external services faked
(VI). The owner's other project, rmd, already runs this stack (rmd ADR 0007), so the versions and
config carry over; its poster look, fonts and tokens do not.

generated from the OpenAPI snapshot), as set up in plan 2's Task 4.

How it fits together:

- Routes reach the API and Better Auth through router context (`context.api`, `context.auth`,
  `context.queryClient`). `main.tsx` passes the real clients; tests pass the harness's. Nothing
  is module-mocked.
- Who is signed in comes from `GET /api/me`. Browsing is public, so its 401 means "signed out"
  and resolves to `null`; there is no app-wide redirect on 401.
- shadcn/ui components (Radix base) are copied into `src/components/ui` and are ours to restyle.
  Their semantic variables map onto the tokens below. Focus comes from one base-layer rule, so
  the components drop their own rings and `outline-none`, and every control has a 44px minimum
  (`min-h-11 min-w-11`). The button and menu come from rmd with that work already done.
- `@/` resolves to `src/` in Vite, Vitest and TypeScript.
- `routeTree.gen.ts` is generated by the router plugin, committed so `tsc` works on a fresh
  checkout, and ignored by Prettier and oxlint.

**Same origin.** In dev, Vite runs on port 5173 with `strictPort` (the `WEB_ORIGIN` in
`.env.example`) and proxies `/api` to the API on port 3000, so a busy port fails loudly instead
of moving to an origin Better Auth doesn't trust. In production the API serves the built app
from `WEB_DIST_DIR` with an SPA fallback (plan 2, Task 3).

### The test harness: the real API in process

`test/harness.tsx` builds the API's `setupTest()` (a fresh in-memory PGlite with the real
migrations) and hands `app.request` to `createApiClient` as its `fetch`, with base URL
`http://amdb.test`. A shared `session` object holds who is signed in: the client sends
`x-test-user` from it on every request, and the stub auth client changes it, so the app and the
API can't disagree. `renderApp(path, { as, seed })` creates the user for `as`, runs `seed` before
the first render, mounts the real router on memory history, and registers teardown (unmount,
cancel queries, close the database). `seed(api)` publishes works, creators, credits and an
adaptation link by submitting with the CC0 agreement and approving as a moderator, so seeded
data takes the real path.

Evidence, from the probe written before anything else:

- Under Vitest's stock `jsdom` environment, importing the API fails before any test runs:

  ```
  FAIL  test/probe.test.ts
  TypeError: The URL must be of scheme file
   ❯ ../api/src/platform/db/open.ts:12:34
       12| export const MIGRATIONS_FOLDER = fileURLToPath(new URL('../../../drizz…
  ```

  The jsdom environment transforms modules with Vite's `client` pipeline, which rewrites
  `new URL('…', import.meta.url)` into a dev-server asset URL, so the migrations path is no
  longer a file URL. Marking the URL `/* @vite-ignore */` was tried and fails the same way.
- A custom environment, `test/environment.ts`, is jsdom's globals with `viteEnvironment: 'ssr'`.
  With it, the same probe passes: `GET /api/health` → `200 { ok: true }`,
  `GET /api/browse?kind=work` → `200 { items: [], nextCursor: null }`, and a request with an
  `AbortSignal` → `200`, all with `window` defined. React, TanStack Router and Testing Library
  render normally under it, and the suite runs without warnings.

So the web tests use the real API, not a fake.

### The look: a reference work

AMDB reads like a library catalog or the index of a reference book: dense, quiet and
typographic, with no cover grid and no cards. The one distinctive device is the printed index's
dotted leader, running from an entry's title to its details ("Spirited Away ······ Film & TV,
2001"). Everything around it stays plain.

- **Fonts.** Source Serif 4 for titles and the wordmark: a text serif drawn for long reading,
  whose optical-size axis lets the same family set a 15px list entry and a 30px heading well.
  Public Sans for interface text: a neutral, institutional sans with clear figures, so details
  and controls stay out of the titles' way. Both are variable and self-hosted with Fontsource;
  no request leaves the origin.
- **Tokens.** Plain custom properties on `:root`, outside Tailwind's `--color-*` namespace so
  they can't collide with shadcn's names. The dark set overrides them under
  `@media (prefers-color-scheme: dark)`, and Tailwind's `dark:` variant uses the same query.

  | Token | Light | Dark | Role |
  | --- | --- | --- | --- |
  | `--paper` | `#f4f5f7` | `#11151d` | page background: cool index-card stock, not cream |
  | `--surface` | `#ffffff` | `#1a1f29` | fields, menus |
  | `--ink` | `#1b2230` | `#e2e5ea` | text; the focus ring |
  | `--ink-muted` | `#565f70` | `#9aa3b2` | details and secondary text |
  | `--rule` | `#d3d8df` | `#2c3442` | hairlines only, never text |
  | `--field-edge` | `#7c8494` | `#6a7385` | the visible edge of text fields, selects and text areas |
  | `--tint` | `#e7eaef` | `#232a36` | hover and selected backgrounds |
  | `--binding` | `#1f5a4c` | `#86c3ad` | links and primary actions: book-binding cloth green |
  | `--danger` | `#a4262c` | `#f08a8a` | errors |

  shadcn's variables map onto them: `background` paper, `foreground` ink, `card` and `popover`
  surface, `primary` binding (with paper text), `secondary` and `accent` tint,
  `muted-foreground` ink-muted, `destructive` danger, `border` rule, `input` field-edge, `ring` ink.
  The outline button keeps `border` in both themes rather than shadcn's dark `input` tint.
- **Contrast** (WCAG, computed from the hex values):

  | Pair | Light | Dark |
  | --- | --- | --- |
  | ink on paper / surface | 14.60 / 15.93 | 14.48 / 13.07 |
  | ink-muted on paper / surface | 5.89 / 6.43 | 7.19 / 6.49 |
  | binding on paper / surface (and paper on binding) | 7.33 / 8.00 | 9.07 / 8.19 |
  | danger on paper / surface | 6.66 / 7.26 | 7.58 / 6.85 |
  | field-edge on paper / surface | 3.45 / 3.76 | 3.83 / 3.46 |

  Every text pair clears AA (4.5:1). The ink focus ring clears the 3:1 non-text minimum against
  every background, and so does a field's edge (WCAG 1.4.11), against the page and against its
  own surface fill; `--rule` (1.31 / 1.43 light, 1.46 / 1.32 dark) is too faint for that and
  stays on decorative rules. Checkboxes and radios are native, drawn by the browser with
  `accent-color: primary`, so their edge isn't a token.
- **Focus and size.** One base-layer rule, `:focus-visible { outline: 2px solid var(--ring);
  outline-offset: 2px }`, and a 44px minimum on every control. `test/a11y-floor.test.tsx` checks
  both, rendering the shell as an anonymous visitor, a contributor and a moderator.

## Alternatives considered

- **rmd's fake API** (`fake-api.ts`, routes answered by hand-written handlers) — the fallback if
  the API couldn't run under jsdom. It can, and a fake drifts from the API it stands in for;
  the constitution wants tests on the real API.
- **A `node` environment for the API with a separate jsdom for rendering** — not needed once
  one environment holds both; it would split each test across two module graphs.
- **Changing the API's migrations path for the web tests** — the API is right as it is; the
  problem is the browser transform, which the custom environment avoids.
- **React Router** instead of TanStack Router — weaker types for params, search params and
  loader data (rmd ADR 0007).
- **Mantine, Chakra or Radix Themes** instead of shadcn/ui — each brings a theme system that
  would fight a quiet catalog look; shadcn's components are source we own.
- **A cover-art grid** for the home page — media sites look like storefronts; AMDB is a
  reference work, has no covers yet, and lists more per screen as an index.
- **Literata** for titles — a fine reading serif, but Source Serif 4's optical sizes serve the
  range from list entries to headings better.
- **A separate static host on another origin** — it would need CORS and cross-site cookies for
  Better Auth.

## Consequences

- Web tests exercise the real routes, rules and database, so an API change that breaks a screen
  fails the web suite. Each test boots PGlite and runs the migrations, under a second per test.
- The web package compiles API source through `@amdb/api/testing`, so the web typecheck also
  covers the API's test helper.
- shadcn components are copied code; updating one means re-running the pinned CLI and
  reapplying the token swap and the 44px floor.
- `GET /api/browse` is ordered by title, so the home page's list is labeled "In the catalog",
  not "Recently added". A recency list needs an API ordering first.
- A change to any choice here gets a superseding ADR.
